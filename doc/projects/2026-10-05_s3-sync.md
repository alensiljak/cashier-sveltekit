# S3 Sync

## Goal

Always-on live backup and sync unit. Minimal setup and infrastructure.

## Design

- Use an S3 bucket as an online storage mechanism. Accessible from the browser directly, no middlemen.
- Synchronize the OPFS storage directly. Skip the local storage step.
- Encrypt the data at rest and decrypt transparently on the fly.
- Encrypt each file individually.
- Each device keeps own manifest. This is the pattern for p2p file sync.

### Decisions

- **Encryption**: AES-256-GCM per object, key derived from a user passphrase (PBKDF2-SHA256, 250k iterations). The salt and a check value live in `key.json` in the bucket, so all devices derive the same key. Object names (paths) are not encrypted, only contents.
- **Credentials and passphrase** stay in device settings (IndexedDB) and are never part of settings backups.
- **Conflicts**: settings and Beancount files are compared by content hash against the hash at the last sync. A change on both sides is never overwritten; the user chooses _Keep this device_ or _Keep bucket_ per file.
- **CRDT stores** (working set, scheduled transactions) are uploaded as one state file per device and merged on download, so they cannot conflict.
- **Scope of the first version**: manual Upload/Download of the selected items. No background sync yet.

### Bucket layout

- `key.json` — key-derivation parameters (the only unencrypted object)
- `manifests/<deviceId>.json` — what each device last uploaded: path → hash, time
- `data/settings.json`, `data/files/<opfs path>` — shared files
- `crdt/xacts/<deviceId>.ydoc`, `crdt/scx/<deviceId>.ydoc` — per-device CRDT state

Code: `src/lib/services/s3Crypto.ts`, `s3SyncPlan.ts` (decisions, no I/O), `s3Sync.ts`, `s3Client.ts`; UI in `src/routes/backup/s3/`.
